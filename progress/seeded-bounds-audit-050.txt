# Seeded rate and count tests: how far each bound sits from chance (session 50, hardening)

Why: session 49 found a test asserting "about 9 in 270" whose real expectation was 2.7, passing by
luck until a list change drew 1. Seeded tests never flake, but any change to how a seed is used
(a new draw, a list change) redraws their counts, so a bound close to the expectation is a test
that fails for no reason later. Rule used here: each bound at least ~4 standard deviations (sd)
from the true rate, or the matching tail probability for a small count.

Expected rates are the code's own (weights, odds tables); "observed" was measured where the
expectation wasn't plain from the table (2,000,000 packs, `rollPack` under S0-odds-2, seeds
9,000,000+).

bounds (toBeGreaterThan / toBeLessThan / toBeCloseTo over a seeded loop). The render lane's tests
are its own and were not audited. Not covered: tests that pin exact seeded outcomes (a named seed
plays a named way); those are meant to change with the code and are regenerated, not bounded.
