AI-TCG Phase 4 — the intended counter triangle, defined and measured against
Session 16, 2026-09-22. Companion to progress/checkpoints.md's Phase 4 entry
and progress/owner-feedback.md's 2026-09-22 entry (which authorized this
session to proceed to Phase 4 of the 2026-09-20 "balance is a systems
problem" entry).

===============================================================================
PART 1 — THE PROPOSED TRIANGLE (Phase 4 item 7's own deliverable: "propose
an explicit counter cycle at a checkpoint")
===============================================================================

Base: the owner's own example in the 2026-09-20 entry, adopted as-is (no
reason found to deviate from it — it matches each faction's established
identity, see each data file's own header comment):

  Null attrition  -->  beats  -->  Aegis stacking
  Aegis walls     -->  beats  -->  Swarm width
  Swarm width     -->  beats  -->  Null's single-target removal
  Cortex is flexible, in the middle: no fixed favoured/disfavoured matchup.

As a directed cycle: Null -> Aegis -> Swarm -> Null, with Cortex outside the
cycle, generalist against everyone.

Targets, exactly as the entry specifies: 55-60% for the intended edge,
45-55% elsewhere, under all three policies (Aggressive/Random/Lookahead).
Applied per pairing:

  Cortex vs Swarm:  45-55% either way (flexible)
  Cortex vs Aegis:  45-55% either way (flexible)
  Cortex vs Null:   45-55% either way (flexible)
  Aegis  vs Swarm:  Aegis 55-60% (Aegis walls beat Swarm width)
  Swarm  vs Null:   Swarm 55-60% (Swarm width beats Null's single-target removal)
  Null   vs Aegis:  Null  55-60% (Null attrition beats Aegis stacking)

Mirror matches (first-player-advantage baseline) are not part of the
triangle — they measure something else (turn-order advantage, not faction
identity) and are reported separately, as balanceReport.ts already does.

PART 3 — THE BACKSTOP NERF PASS (2026-09-20 entry's priority-ordered
candidate list, applied in order, measured after each step)
===============================================================================

Starting point: the Part 2 table above. Full raw output for the FINAL state
(after all three steps below) follows this write-up in Part 5; intermediate
steps' raw balanceReport.ts output was not separately committed (300 seeds x
3 policies each run took ~14s; re-running from git history reproduces any
of them exactly, since every run is seed-deterministic) — only the specific
numbers relevant to judging each step are recorded here, honestly, not
cherry-picked.

--- Step 1: "redesign Segmentation Fault so its effect is conditional or
    temporary" ---

Segmentation Fault (Null's Rare Directive, cost 4, "enemy units get -1/-0")
was unconditional since it was created. Redesigned to conditional: "While
you control 2 or more units, enemy units get -1/-0" — a real soft counter
(clear Null's board and the debuff turns off, not just a smaller number),
not a duration hack. This needed one small piece of NEW generic engine work,
not a card-only change: `Ability.condition` (already used to gate
onPlay/activated abilities) had never been read for the "static" trigger —
`effects/statics.ts`'s `staticModifiersFor` now checks it for every static
source, the same generic Condition union every other trigger already uses.
Real, unscripted-play evidence that the toggle fires both ways, not just a
synthetic fixture: `progress/sample-match-017-segfault-condition.txt` (a
real LookaheadAgent-vs-LookaheadAgent match, seed 31, Null vs Cortex, where
Null's board drops to 1 unit — aura observably INACTIVE, enemy attack at
full base value — then rebuilds to 2 units — aura observably ACTIVE, the
same enemy unit's live attack reads 1 lower). Also pinned by a dedicated
whitebox test (`engine/test/nullFaction.test.ts`).

Measured effect: Aegis-vs-Null moved from 78.3%/78.3%/67.7% to
76.7%/77.0%/67.7% (Aggressive/Random/Lookahead) — real but tiny. Read:
Null's kit is wide enough (Fork Bomb's two tokens, Stray Fragment, Glitch
Seed, Corruption Patch, etc.) that it reaches or holds 2+ units on the board
almost every game once it's established, so the condition is true most of
the time it matters. The card is now a genuine soft counter in principle
(and demonstrably toggles in real play), but it wasn't a big enough lever on
its own to move the number.

--- Step 2: "reduce Fork Bomb, Segfault Handler and Corrupted Process to 2
    copies" ---

Segfault Handler was already at 1 copy (below the target), nothing to do.
Corrupted Process cut 3 -> 2 copies. Fork Bomb was NOT cut this round — see
the honest constraint below. `Corrupted Process's draw is now part of
Null's power ... on the table` per the 2026-09-22 owner-feedback entry, so
this is the specific card that entry called out.

Real constraint hit and resolved, not glossed over: the Null pool was
sitting EXACTLY at the Phase 3 lint's 25% removal/debuff cap (8/32 copies).
Cutting a non-removal card's copy without backfilling immediately fails the
lint (same removal numerator, smaller denominator = higher percentage) —
confirmed by actually running the test suite and watching
`poolLint.test.ts`/`matchSmoke.test.ts` fail with exactly that message
before backfilling. Null Shell (Uncommon, was 2 copies, cap 3) is the only
card in the pool with headroom under its rarity's copy cap, and absorbed
exactly the one cut Corrupted Process needed to stay lint-legal (32 total
copies, 8 removal copies, 25.0%, unchanged). That headroom is now used up —
a second cut (Fork Bomb) has no legal backfill left without shrinking the
deck or trimming one of the three removal cards the original Phase 3 pass
explicitly protected as core identity (Kernel Panic/Null Singularity/Null
Pointer). Left as a named, specific option for a future session (see
quality-debt.md), not silently dropped.

Measured effect (cumulative, on top of step 1): Aegis-vs-Null moved to
76.7%/75.7%/67.0%. Swarm-vs-Null (Lookahead) moved 67.3% -> 63.7% Null — the
single largest individual-step movement this session found, though it
partially reverted after step 3 (see below), suggesting some of it may be
sampling noise from the full-deck reshuffle rather than a clean isolated
effect of this one change.

--- Step 3: "make Entropy Harvester scale off the enemy graveyard" ---

Entropy Harvester's static "attack = 1 + graveyard size" scaling source
changed from `controllerGraveyardSize` (Null's own graveyard — which fills
for free as a side effect of Null's normal attritional play, snowballing
regardless of how the match is going) to a new, generic
`opponentGraveyardSize` ScalingSource (added to `cards/types.ts`,
`effects/scaling.ts`, and `agents/lookaheadAgent.ts`'s own scaling context —
both graveyards are public zones, so no new redaction work was needed).
This ties the card's growth to actually having killed the OPPONENT's stuff,
which is slower early and gives nothing in a match Null is losing the
attrition race. Proven with a corrected whitebox test
(`engine/test/nullFaction.test.ts` — the controller's own graveyard filling
up is now asserted to NOT move this card's attack at all, only the
opponent's does) and exercised for real across every game this session's
balance runs played (766-876 "drawn" instances per policy in the final
report below — a card that never fires would show 0 played, not hundreds).

Measured effect (cumulative): Aegis-vs-Null moved to 78.0%/72.0%/67.7% — a
real further drop under Random specifically (75.7% -> 72.0%), the largest
single movement toward the target this session achieved, but Aggressive and
Lookahead both essentially reverted to their pre-step numbers.

--- Cumulative result across all three steps, honestly assessed ---

  Aegis vs Null:   Aggressive 78.3% -> 78.0%  (flat)
                   Random     78.3% -> 72.0%  (-6.3pts, real)
                   Lookahead  67.7% -> 67.7%  (flat)
  Swarm vs Null:   Aggressive(Null) 55.3% -> 56.0%  (flat/slightly worse)
                   Random(Null)     80.7% -> 79.0%  (-1.7pts, small)
                   Lookahead(Null)  67.3% -> 67.3%  (flat)

Both pairings remain triple-flagged after all three steps. This is the same
honest pattern sessions 8/10/11 already found and documented for this exact
matchup: individual Null card nerfs move the Random-policy number
measurably but barely touch Aggressive/Lookahead. Per-card instrumentation
in the final report (Part 5) names the likely reason more precisely than
prior sessions could: Kernel Panic (played win rate 73.5%/88.7%/75.5% across
the three policies) and Null Singularity (67.1%/73.7%/70.2% -> now reads
similarly after this session's changes) are extreme outliers against a pool
that otherwise clusters 45-60% — neither was touched this session. Step 4 in
the priority list ("cost increases") was NOT attempted: both cards already
sit at their faction-mirror equivalents' cost (Kernel Panic 5 = Aegis
Warden's 5; Null Singularity 6 = Prime Aegis's 6), so raising them further
would make Null's top end cost strictly more than every other faction's
equivalent-tier card for the first time — a real cross-faction curve
decision, not a same-shape nerf like the first three steps, and one this
session did not judge itself entitled to make unilaterally. Flagged as the
most concrete, data-backed next step for whoever continues this (see
quality-debt.md and notes-for-owner.md).

===============================================================================
PART 4 — CORTEX-VS-SWARM: MEASURED, NAMED, NOT FIXED THIS SESSION
===============================================================================

Per Part 2, Cortex triple-flags against Swarm and this is explicitly a
Phase-4-scope finding ("Cortex-vs-Swarm gets picked up at the Phase 4
re-measure with everything else" — 2026-09-20 entry). Unlike Aegis-vs-Null,
there is no owner-pre-authorized backstop mechanism for this pairing (the
"Null dominance" entry's nerf-priority list is Null-specific). Fixing it
would mean either nerfing Cortex or buffing Swarm/Aegis — a real card-set
design decision this session chose not to make unilaterally in the same
pass as executing an already-authorized Null nerf, per this project's own
standing practice of proposing before unilaterally changing another
faction's identity. Left honestly flagged, not silently dropped — see
`progress/checkpoints.md`'s Phase 4 entry for the specific proposal put to
the owner, and `progress/quality-debt.md` for the debt entry.
