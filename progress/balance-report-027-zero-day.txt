AI-TCG balance report 027: the 3 Season 0 Zero-Day cards, measured (session 40)
Owner 2026-10-16: "measure the strength with the same fairness test as signature cards ... propose the cap
with the measurements". Owner 2026-10-18: the 3 designs, at starting numbers; "check that agents use both
modes of each card, not always the same one".

The test (dev/zeroDayFairness.ts; the signature test's shape, for a deck card):
  - Reference: every faction plays its shipped deck with one slot changed: one spare copy of a card
    (a removal card when the Zero-Day card counts as removal, so the deck's removal share doesn't move)
    becomes a plain Neutral stand-in of the same cost with no ability. A Unit's stand-in keeps the
    Zero-Day card's body (2/4, 3/6), so what is measured is the modes alone; Kill Switch's is a 7-cost 4/8.
    The signature zone holds the plain 3/6 reference signature, as in the signature test.
  - Candidate: one faction's stand-in becomes the Zero-Day card, in the same deck position (same shuffle,
    same games until it is drawn), the other three keeping theirs. All four factions take a turn.
  - Each edge's change is the paired mean of per-seed differences (a win 1, a loss or draw 0), with its
    95% interval. 10,000 games per pairing, LookaheadAgent on both sides (edge-measure seeding).
  - "LOCKED to X": the same card made non-modal in mode X, so the agent can't pick the other. It plays
    exactly like the modal card in that mode. It answers "is the agent's pick worth anything?"
    Caveat: LookaheadAgent values a plain unit by body and onPlay only, so a LOCKED unit whose mode is a
    static or an onDeath is played less often than the modal card (it gets no mode value), and LOCKED
    Lights Out is cast far less often than Wipe. Compare the "played in" counts.

Commands (from engine/), all seeded, about 4 minutes each on one core:
  npx tsx src/dev/zeroDayFairness.ts reference --seeds 10000 --out ref.json
  npx tsx src/dev/zeroDayFairness.ts candidate --card S0-ZD1 [--force outbreak] --ref ref.json --out zd1.json
  npx tsx src/dev/zeroDayFairness.ts report --ref ref.json zd1.json ...

Findings:
  1. Every card plays stronger than a plain card of its cost on every edge, as the owner intends
     ("slightly stronger"), and no card breaks the game: the largest move is 4.50 points (agent choosing)
     and 6.04 points (Patient Zero locked to Carrier).
  2. The mode choice is real but the reference agent reads it badly in two of three cards:
     - Patient Zero: Carrier is clearly the stronger mode (4.69 vs 0.93 mean), yet the agent picks Outbreak
       about 3 times in 4. Its pick is worth less than always picking Carrier.
     - Kill Switch: per cast, Lights Out moves edges more than Wipe (it is cast in under a third as many games), yet the
       agent essentially never picks it. Both modes are not used: the owner's check fails here.
     - Root Access: the agent picks the stronger mode (Privilege Escalation) most of the time, and the
       modal card is stronger than either locked version, because the mode value also makes the agent
       play it more often.
     Cause (agents/lookaheadAgent.ts): an ongoing aura is valued at half its size once, and a status at
     0.6 x the unit's attack whatever its duration. A 2-turn stun of the whole board scores like a
     one-turn tap, and +1/+1 to every unit for the rest of the game scores like a small one-off buff.
  3. Because the fairness test measures through this agent, a better chooser would make Patient Zero
     stronger (towards its Carrier 6.04) and Kill Switch somewhat stronger. A cap set on today's numbers
     would be set against an agent that leaves strength on the table.
